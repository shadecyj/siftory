# Siftory Desktop Distribution

## V0.1 desktop target

Siftory V0.1 ships a **Windows x64 Tauri installer** for interview and portfolio demonstrations.

- Product artifact: `Siftory_0.1.0_x64-setup.exe`
- Supported system: Windows 10/11 x64
- Installer type: NSIS, per-user installation
- Browser runtime: WebView2 system runtime; the installer embeds a small bootstrapper when it is absent
- User prerequisite: none — users do **not** need to install Node.js, npm, PostgreSQL, or a browser extension

The package uses Tauri for the native window and lifecycle. To preserve the existing Search Engine, Trust Engine, Knowledge Engine, API routes, and PGlite persistence intact, it starts a bundled local Siftory runtime on a random `127.0.0.1` port. It is not exposed to the LAN.

## What the installer includes

```text
Tauri native shell
  + bundled local Siftory runtime
  + Next standalone server
  + PGlite + Drizzle migrations
  + default Replay demonstration mode
```

The package deliberately contains no API keys. Its local knowledge data is stored under the current user's Windows local application-data directory, not next to the installed executable.

The desktop application also includes the Round 0 global language preference (`中文（简体）` / `English`). It changes Siftory interface copy and future run presentation only; source titles, evidence excerpts, saved Search Notes, and personal notes remain in their original language so evidence traceability is preserved.

## First-run experience

The desktop package opens in **Replay · 离线样例** mode, so it is safe to run immediately after installation. On the home page, click the example button and run:

```text
Python 怎么删除 dict key？
```

This demonstrates the full V0.1 chain: progress states, claim/evidence/source relationships, contextual confidence, and Save to Search Note.

Live web search needs a user-owned model key and search-provider key. Keys must never be embedded in a public GitHub Release.

To opt in, open Siftory **Settings** and click the visible **Configure Live API** action. It opens the desktop application's native **Settings / Credentials** panel, which provides an explicit Save → Test → Apply flow and only reports redacted configuration state back to the Siftory workspace. On Windows, its local credential boundary is protected with Windows Credential Manager; plaintext keys are not returned to the loopback web workspace, `/api/settings/runtime-status`, logs, PGlite, Search Notes, or screenshots generated by the application.

Connection tests run only after the user explicitly chooses **Test**. They can contact the selected search/model provider and may consume quota or incur provider charges. Replay remains available if a profile is missing, fails validation, or is cleared.

## Build and collect a release asset

```powershell
npm ci
npm run desktop:build
```

The command performs the production web build, prepares the standalone runtime, builds the Tauri installer, and copies the publishable files to:

```text
dist/desktop/
  Siftory_0.1.0_x64-setup.exe
  SHA256SUMS.txt
```

Attach both files to the GitHub Release. The SHA-256 file lets downloaders verify that their installer matches the release artifact.

`desktop:build` finishes with a fail-closed credential-pattern scan over the prepared runtime and copied release assets. It never prints a matching value; investigate a failed scan locally and rotate any exposed credential before rebuilding.

## Release notes to include

- `Windows x64 only` for this V0.1 desktop preview.
- `Replay demonstration included; Live provider keys are not included.`
- `Live is opt-in through the native Settings / Credentials panel. Connection tests may consume provider quota or incur charges.`
- `API keys are never accepted by the browser workspace and are never bundled into release assets.`
- The binary is not code-signed yet, so Windows SmartScreen may show a warning on first download. Only distribute it from the project GitHub Release and publish the corresponding checksum.
- The source build remains the path for configuring a personal DeepSeek/Tavily or Brave live runtime today.

## Desktop acceptance checks

Before publishing a new installer:

1. Run `npm run check`.
2. Run `npm run desktop:build`.
3. Confirm `dist/desktop/` contains the installer and `SHA256SUMS.txt`.
4. On a clean Windows account or VM, install the `.exe` and launch Siftory.
5. Switch between Chinese and English, relaunch, and verify the preference persists while the Replay evidence remains original.
6. Use the Replay example, open its evidence, save the note, and verify it appears in Library after relaunch.
7. Confirm Settings reports the active Runtime without displaying a key. If validating Live on a disposable test profile, use the native Credentials panel, explicitly test it, apply it, run one search, then clear the profile and confirm Replay fallback.

For source-run development, do not use the desktop credential panel as a substitute for environment management: configure server variables in an untracked `.env.local` and use `/settings` only to inspect redacted state. See [SECURITY.md](../SECURITY.md) for the public-repository and credential-handling checklist.
